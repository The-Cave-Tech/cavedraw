# Reading the render-fidelity numbers

`CATALOGUE.md` is regenerated by `tools/fonts-compare/build_catalogue.py`, so nothing
written by hand belongs in it. That script's header points here, and this file is tracked in git where the generated
catalogue is not.

## RMSE against the noise floor

An RMSE in `CATALOGUE.md` compares our export to the original through one rasteriser,
so it mixes what we got wrong with the fact that two renderers disagree about
antialiasing. On these pages most of every number is the second.

`tools/fonts-compare/render_floor.py` separates them:

- renders the ORIGINAL with poppler and with mutool — the disagreement that is not
  about us;
- renders our export with poppler — a like-for-like comparison, one renderer both
  sides;
- renders our export with both engines — a file two renderers read the same way is a
  file that says clearly what it means.

```bash
python tools/fonts-compare/render_floor.py ../samples/3464_LILLIE_View_A_Sides_color.pdf \
    artifacts/catalogue/ours.pdf 12 150
```

## Transparency-DesignGuide.pdf

The same measurement says something different here, which is why it is worth
recording rather than generalising from one file:

| page | excess mean | our file's own noise |
|---|---|---|
| 1 | **+12.10** | 7.61 |
| 3 | **+6.29** | 4.56 |
| 7 | **+10.44** | **19.57** |

Pages 1, 3 and 7 have real excess. Page 7 is the concrete one and the place to start:

- In the preview image's box, the original renders the red rounded shape.
- Our export renders **nothing in poppler** and **a black square in mutool** —
  129,220 dark pixels against the original's ~100.
- The image is 185x174 RGB and an SMask hides it in the original. Our copy is drawn
  fully visible, so **the SMask is the thing to look at next**, not the image data:
  its bytes now pass through byte-exact with `/Filter /DCTDecode` intact, and fixing
  that changed the page's numbers by nothing measurable.
- The red rounded shape is also missing from our render, which is a second question in
  the same box: the model holds it as a path with a red fill.

## LILLIE's clip structure

`tools/fonts-compare/clip_operators.py` prints every clip in a file with its extent
and the stream it came from. LILLIE contains exactly two rectangles in the whole
document — the page box (17 streams) and the preview image's own (1 stream) — and both
are already matched on export, in the page's own frame: the original wraps its page
content in `1 0 0 1 36 36 cm` and we do not, which is why the first reads
`0..540, 0..720` and ours `36..576, 36..756`. The same rectangle.
